# 《外星人入侵 2.0》课程作业

> 基于本项目的现有代码（《Python 编程：从入门到实践》第 12～14 章完整版），在不破坏原有玩法的前提下完成以下功能。
>
> **必做 60 分 + 进阶 20 分 + 工程质量 20 分 = 100 分**

## 一、学习目标

完成本作业后，你应当能够：

- 用状态变量管理游戏的运行、暂停和结束状态；
- 使用 JSON 文件保存并容错读取游戏数据；
- 为现有类扩展新功能，而不是把所有代码堆进主类；
- 用计时逻辑实现限时效果，并正确处理暂停；
- 编写可复现的自测记录，说明功能是否达到验收标准。

## 二、环境与运行

- Python 3.9 及以上
- pygame 2.5 及以上
- 不得引入 pygame 以外的第三方库
- 游戏必须仍能通过 `python alien_invasion.py` 启动

## 三、必做任务（60 分）

### 任务 1：暂停与继续（20 分）

在游戏进行中按 `P` 键暂停，再按 `P` 键继续。

**功能要求**

1. 只有游戏处于进行中时，`P` 键才有效；开始界面和游戏结束界面按 `P` 无效果。
2. 暂停期间：
   - 飞船、子弹、外星人全部静止；
   - 不能移动飞船、不能发射子弹；
   - 不产生得分，不触发碰撞，不推进任何限时效果；
   - 除 `P`（继续）和 `Q`（退出）外，忽略其他键盘输入。
3. 屏幕中央显示大号文字 `PAUSED`，并在其下方显示 `Press P to Resume`。文字下方需要有不透明背景，保证能看清。
4. 恢复后游戏从暂停时的状态继续，飞船、子弹、外星人不得出现位置跳变。
5. 游戏结束并重新开始后，必须处于“未暂停”状态。

**验收方式**

- 暂停后按住方向键、连按空格 2 秒：飞船和外星人坐标不变，子弹数量不增加；
- 连续按两次 `P` 后，飞船恢复移动，外星人恢复移动；
- 在开始界面按 `P`，不显示 `PAUSED`。

### 任务 2：最高分持久化（20 分）

当前最高分只保存在内存中，关闭程序就会丢失。请把它保存到文件中。

**功能要求**

1. 在项目根目录（与 `alien_invasion.py` 同级）使用 `high_score.json` 保存最高分，格式为：

   ```json
   {"high_score": 1250}
   ```

2. 程序启动时读取该文件，并把读到的值用于记分牌显示。
3. 每次刷新最高分后立即写回文件；即使玩家直接按 `Q` 或关闭窗口退出，最高分也不能丢失。
4. 文件不存在、内容为空、不是合法 JSON、字段缺失、类型不是非负整数时，一律按 `0` 处理，程序不得崩溃；下一次破纪录时正常覆盖该文件。
5. 文件路径必须基于脚本位置计算，不能依赖当前工作目录。作业验收时会从其他目录启动程序。
6. 重新开始游戏时最高分保留，不得被清零。

**验收方式**

1. 打出一局高分 → 退出 → 重新启动，最高分仍然显示；
2. 把 `high_score.json` 内容改成 `not json` → 启动游戏不崩溃，最高分显示 0；
3. 在项目上一级目录执行 `python alien_invasion/alien_invasion.py`，最高分读写仍然正常。

### 任务 3：游戏结束界面（20 分）

最后一艘飞船被撞毁后，当前版本只是重新显示 `Play` 按钮。请增加明确的游戏结束界面。

**功能要求**

1. 生命值变为 0 时进入游戏结束状态：停止更新飞船、子弹和外星人，清空场上子弹。
2. 屏幕中央显示：
   - 大号文字 `GAME OVER`；
   - 最终得分，格式为 `Score: <得分>`；
   - 提示文字 `Click Play to Restart`。
   文字下方需要有不透明背景，保证能看清。
3. 开始界面不能显示 `GAME OVER`；只有真正输掉游戏后才显示。
4. 游戏结束状态下点击 `Play` 能开始新的一局，并且必须正确复位：
   - 得分归零、关卡回到 1、生命恢复为 3；
   - 飞船、子弹、外星人、掉落道具全部重新创建或清空；
   - 速度恢复到初始值；
   - 暂停状态、游戏结束状态、限时效果全部清除；
   - 最高分保留。

**验收方式**

- 连续损失 3 艘飞船后，`GAME OVER`、最终得分和重开提示同时出现，游戏元素不再移动；
- 点击 `Play` 后，得分 0、关卡 1、3 艘飞船、速度恢复初始值，且可以正常游玩；
- 新一局中最高分仍显示上一局的纪录。

## 四、进阶任务（20 分）：道具系统

消灭外星人时，有一定概率掉落道具。道具从屏幕顶部下落，飞船碰到即拾取。

**道具类型**

| 类型 | 绘制标记 | 效果 |
| --- | --- | --- |
| 护盾 | 蓝色方块 + `S` | 抵挡下一次会导致生命值减少的事件，然后消失 |
| 连发 | 橙色方块 + `R` | 持续 8 秒，子弹上限从 3 提升到 6 |
| 加命 | 绿色方块 + `+` | 生命值 +1，最多 5 艘 |

**功能要求**

1. 每消灭一个外星人，按 `settings.py` 中的概率决定是否掉落道具；道具类型在三种中随机。
2. 道具以固定速度下落，碰到飞船即被拾取并从屏幕移除；落到屏幕底部则自动消失。
3. 护盾抵挡一次“飞船被撞”事件：
   - 生命值不减少；
   - 护盾立即消失；
   - 仍按原有流程重置舰队、清空子弹、让飞船回到屏幕底部中央。
4. 连发效果：
   - 持续 8 秒，期间子弹上限为 6；
   - 结束时恢复为 3；
   - 暂停期间不计时，恢复后继续倒计时；
   - 再次拾取连发道具时，持续时间重置为 8 秒。
5. 加命效果：
   - 生命值 +1，最多 5 艘；
   - 已达到 5 艘时拾取，道具消失，生命值不变；
   - 记分牌上的飞船图标数量同步更新。
6. 生命值减少时（无护盾保护），清空场上所有掉落道具，并清除连发效果。
7. 暂停时道具停止下落，也不触发拾取；重新开始游戏时清空所有道具和效果。
8. 屏幕右上角（关卡数下方）显示当前生效的状态，例如：

   ```text
   SHIELD
   RAPID FIRE 5.2s
   ```

9. 以下参数必须放在 `settings.py` 中，不得硬编码：

   - 掉落概率（建议 `0.12`）
   - 下落速度（建议 `2.0`）
   - 连发持续时间（`8` 秒）
   - 连发时的子弹上限（`6`）
   - 生命值上限（`5`）

10. 为便于验收，道具生成逻辑必须能单独调用，例如提供 `spawn_powerup(kind)` 方法，可强制生成指定类型的道具。

**验收方式**

- 强制生成护盾并拾取，撞上外星人后生命值不变、护盾消失、舰队重置；
- 强制生成连发并拾取，子弹上限变为 6，HUD 显示倒计时；暂停 2 秒后剩余时间不变，8 秒后恢复为 3；
- 强制生成加命并拾取，飞船图标增加；达到 5 艘后不再增加；
- 游戏结束后重开，道具、护盾、连发状态全部消失。

## 五、工程质量要求（20 分）

1. **模块划分**：新增的道具、HUD 等逻辑应放进独立模块或独立类，不要把全部代码继续堆进 `AlienInvasion`。主类适合负责协调，不适合承担所有细节。
2. **可配置**：新增的数值（概率、速度、时长、上限）必须放进 `settings.py`。
3. **健壮性**：文件读写、JSON 解析、类型转换都要处理异常；任何输入或损坏的数据都不能导致崩溃。
4. **注释与文档**：新增代码使用中文注释，说明“为什么”而不是复述代码；更新 `README.md`，写清新增操作和道具规则。
5. **自测记录**：提交一份自测表，逐条列出验收项的通过情况；未通过或未完成的项要如实注明。
6. **不得破坏原功能**：原有移动、射击、碰撞、计分、关卡提速、最高分显示必须全部正常。

## 附录 A：常见失分点

1. 暂停只停止了画面刷新，但仍在更新位置或计时；
2. 每次拾取道具都新建计时器，导致多个计时器互相覆盖；
3. 最高分只在新一局开始时保存，按 `Q` 退出就丢失；
4. JSON 文件损坏时直接抛异常，游戏无法启动；
5. 重新开始只重置了得分，忘记重置关卡、速度、暂停状态和道具效果；
6. 道具类直接访问 `AlienInvasion` 的大量内部属性，导致模块之间强耦合；
7. 用绝对路径保存最高分，换一台电脑就无法运行。

## 附录 B：实现提示（可选阅读）

- 暂停建议使用布尔状态，并在主循环中统一判断：
  `if self.game_active and not self.game_paused:`；
- 最高分读写可以放在 `GameStats` 中，或新建独立模块；路径用 `Path(__file__).resolve().parent` 计算；
- 游戏结束可以增加 `game_over` 标志，与“尚未开始”区分开；
- 道具建议新建 `PowerUp(Sprite)` 类，用字符串区分类型，绘制时使用 `pygame.draw` 和文字，无需新增图片；
- 限时效果不要依赖“暂停了多少帧”，应累计游戏处于运行状态的时间。
